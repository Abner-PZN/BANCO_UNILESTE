1. Modelo Conceitual

Este modelo representa o processo comercial da Unileste Comércio LTDA., responsável pela venda de produtos a distribuidores, emissão de notas fiscais, controle de pagamentos e rastreabilidade dos lotes adquiridos junto aos fornecedores.

Entidade Relacionamento Cardinalidade
Distribuidor Pedido 1:N
Pedido Produto N:N
Pedido Nota Fiscal 0:1
Pedido Pagamento 1:N
Fornecedor Compra 1:N
Compra Lote 1:N
Produto Lote 1:N

2. Fluxo de Dados

Fornecedor → Compra → Lote → Produto → Pedido → Nota Fiscal → Pagamentos.

3. Convenções

SGBD: MySQL 8 (InnoDB).

Codificação: UTF8MB4.

Prefixos utilizados:

  • ID – Identificador
  • NM – Nome
  • DT – Data
  • TP – Tipo
  • QT – Quantidade
  • VL – Valor
  • CD – Código

4. Estrutura das Entidades (Dicionário de Dados)

01. Distribuidor

Armazena os dados cadastrais dos distribuidores parceiros.

DISTRIBUIDOR = id_distribuidor + nome + CNPJ + endereço + telefone
Atributo Tipo Obrigatório Significado
id_distribuidor INTEGER Sim (PK) Identificador único.
nome VARCHAR(120) Sim Razão Social.
CNPJ VARCHAR(18) Sim CNPJ único.
endereço VARCHAR(200) Sim Endereço.
telefone VARCHAR(20) Não Telefone.

Índices: PK(id_distribuidor), índice em CNPJ.

02. Produto

Representa os produtos comercializados.

PRODUTO = id_produto + nome + tipo + preço
Atributo Tipo Obrigatório Significado
id_produto INTEGER Sim (PK) Identificador único.
nome VARCHAR(120) Sim Nome comercial.
tipo VARCHAR(50) Sim Tipo do produto.
preço DECIMAL(10,2) Sim Preço de venda.

Índices: PK(id_produto).

03. Pedido

Formaliza a solicitação de compra realizada por um distribuidor.

PEDIDO = id_pedido + data + status + id_distribuidor
Atributo Tipo físico Obrigatório Significado e relevância
id_pedido INTEGER Sim (PK) Identificador único do pedido.
data DATE Sim Data de criação do pedido.
status VARCHAR(20) Sim Situação do pedido (pendente, pago, entregue).
id_distribuidor INTEGER Sim (FK) Identifica o distribuidor responsável pelo pedido.

Índices: PK(id_pedido); índice em id_distribuidor; índice em status.

04. Relacionamento Pedido-Produto

Representa a associação entre pedidos e produtos, incluindo a quantidade solicitada de cada item.

PEDIDO_PRODUTO = id_pedido + id_produto + quantidade
Atributo Tipo físico Obrigatório Significado e relevância
id_pedido INTEGER Sim (FK) Pedido que contém o produto.
id_produto INTEGER Sim (FK) Produto solicitado no pedido.
quantidade INTEGER Sim Quantidade do produto solicitada no pedido.

Índices: índice composto em id_pedido + id_produto; regra: quantidade maior que zero.

05. Nota Fiscal

Documento fiscal emitido quando um pedido é faturado.

NOTA_FISCAL = id_nf + número + data + valor + id_pedido
Atributo Tipo físico Obrigatório Significado e relevância
id_nf INTEGER Sim (PK) Identificador único da nota fiscal.
número VARCHAR(20) Sim Número oficial da nota fiscal.
data DATE Sim Data de emissão da nota.
valor DECIMAL(10,2) Sim Valor total faturado.
id_pedido INTEGER Sim (FK) Pedido relacionado à nota fiscal.

Índices: PK(id_nf); índice único em id_pedido.

06. Pagamento

Registra os pagamentos realizados para um pedido.

PAGAMENTO = id_pagamento + Data + Valor + Forma + id_pedido
Atributo Tipo físico Obrigatório Significado e relevância
id_pagamento INTEGER Sim (PK) Identificador único do pagamento.
Data DATE Sim Data do pagamento.
Valor DECIMAL(10,2) Sim Valor pago.
Forma VARCHAR(30) Sim Forma utilizada (PIX, Boleto, Transferência etc.).
id_pedido INTEGER Sim (FK) Pedido referente ao pagamento.

Índices: PK(id_pagamento); índice em id_pedido; índice em Data.

07. Fornecedor

Representa os fornecedores responsáveis pela produção dos itens comercializados.

FORNECEDOR = id_fornecedor + id_nome + CNPJ + endereço + telefone
Atributo Tipo físico Obrigatório Significado e relevância
id_fornecedor INTEGER Sim (PK) Identificador único.
id_nome VARCHAR(120) Sim Razão Social.
CNPJ VARCHAR(18) Sim CNPJ do fornecedor.
endereço VARCHAR(200) Sim Endereço.
telefone VARCHAR(20) Sim Telefone para contato.

Índices: PK(id_fornecedor); índice único em CNPJ.

08. Compra

Representa as compras realizadas junto aos fornecedores.

COMPRA = id_compra + data + id_fornecedor + Valor
Atributo Tipo físico Obrigatório Significado e relevância
id_compra INTEGER Sim (PK) Identificador único da compra.
data DATE Sim Data da compra.
id_fornecedor INTEGER Sim (FK) Fornecedor responsável.
Valor DECIMAL(10,2) Sim Valor total.

Índices: PK(id_compra); índice em id_fornecedor.

09. Lote

Controla os lotes recebidos no estoque e sua rastreabilidade.

LOTE = id_lote + id_compra + id_produto + quantidade + validade
Atributo Tipo físico Obrigatório Significado e relevância
id_lote INTEGER Sim (PK) Identificador único do lote.
id_compra INTEGER Sim (FK) Compra de origem.
id_produto INTEGER Sim (FK) Produto armazenado.
quantidade INTEGER Sim Quantidade disponível.
validade DATE Sim Data de validade do lote.

Índices: PK(id_lote); índice em id_compra; índice em id_produto; índice em validade.

5. Log de Acesso (Metadado Operacional)

As tabelas do sistema utilizam o mecanismo de auditoria do MySQL 8 por meio do audit_log, registrando operações de leitura, inserção, atualização e exclusão.

Os registros são utilizados para rastreabilidade das operações administrativas, financeiras e de estoque, permitindo auditoria das alterações realizadas no banco.
